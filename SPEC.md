# doxBot — спецификация

Личное хранилище семейных документов с доступом через Telegram Mini App.
Зафиксировано: 20.08.2026, обновлено: 30.09.2026

## Идея

Документы всей семьи (люди + объекты вроде недвижимости/авто) в одном месте.
Поиск, просмотр ключевых полей и скачивание — через Telegram-бота и Mini App
внутри Telegram. Загрузка и редактирование — только через отдельную
веб-админку, закрытую паролем, с компьютера.

## Технологии

- Backend: FastAPI + SQLite
- Админка: Jinja2-шаблоны, **светлая тема** (изначально планировалась тёмная
  как в OilTrade, потом сознательно поменяли на светлую и современную)
- Бот: aiogram3
- Mini App: HTML/CSS/JS (без фреймворков) + telegram-web-app.js SDK,
  светлая тема
- Файлы: хранятся в Google Drive пользователя, бэк должен стримить их через
  Drive API по сохранённой ссылке, без локального кеша — **пока не
  реализовано**, см. раздел "Скачивание файла"
- Хостинг: VPS Hostkey 31.57.143.110 (Нидерланды, Ubuntu 24.04) — старый
  VPS (82.22.187.68) умер в сентябре 2026, все проекты переезжают на новый.
  Планируется тот же паттерн, что у остальных ботов: git на сервере,
  systemd + nginx + Let's Encrypt, поддомен DuckDNS

## Модель данных

### subjects (субъекты)

Единый список без деления на людей/объекты: Я, Жена, дети,
Квартира на Ленина, Kodiaq и т.д. — все в одной таблице.
- id, name, created_at

### folders (папки)

Группируют документы внутри субъекта (например у Квартиры — папка
"Аренда" и папка "Ипотека" отдельно, чтобы не мешать в кучу).
- id, subject_id, name, created_at

### categories (категории-ярлыки)

Сквозные лейблы поверх документов, не привязаны к субъекту.
Стартовый набор: Паспорт, Загран, Полис ОМС, СНИЛС, ИНН, СОР, СОБ.
Редактируются и добавляются вручную через админку.
- id, name, created_at

### documents (документы)

- id, subject_id, folder_id (nullable), category_id
- title, series, number, issued_by
- issue_date — дата выдачи (по этому полю сортировка "самый свежий")
- valid_from, valid_until — сроки действия (nullable)
- notify_before_expiry — bool
- notify_period — 'week' | 'month' | '2months' (один вариант)
- is_primary — bool. У одного субъекта в одной категории может быть
  несколько "основных" одновременно (например два актуальных полиса)
- drive_link — ссылка на файл в Google Drive, вставляется вручную
- drive_file_id — парсится из drive_link автоматически при сохранении
- created_at, updated_at

### documents_fts — виртуальная таблица FTS5

Создана в базе (`database.py`, с триггерами синхронизации при
insert/update/delete), но **сейчас не используется** — реальный поиск
в `api.py` сделан проще, через `LIKE` по title/series/number/issued_by.
Для текущих объёмов (десятки-сотни документов) разницы в скорости нет.
FTS5-таблица оставлена как задел на будущее, если documents вырастет
на порядки.

## Доступ и защита (топ-приоритет проекта)

Два независимых слоя:

1. **Проверка initData** (`telegram_auth.py`) — каждый запрос к JSON API
   (`api.py`) проверяется HMAC-подписью по алгоритму Telegram (секрет —
   BOT_TOKEN), плюс отклоняются протухшие initData (старше суток).
2. **Whitelist по telegram user_id** — `ALLOWED_TELEGRAM_IDS` в `.env`
   (сейчас там только Александр, 267982336). Даже с валидной подписью,
   если id не в списке — 403.

Плюс третий, платформенный слой — в BotFather включена настройка
**Restrict bot usage** (Access → Restrict bot usage), она не даёт
посторонним вообще написать боту. Работает независимо от наших
собственных проверок, как доп. подстраховка.

`DEV_MODE` в `.env` — аварийный рубильник для локальной разработки без
реального Telegram-клиента (пропускает запросы без initData). **На проде
должен быть строго `false`** — сейчас так и стоит, включать обратно
только для локальных тестов без Telegram.

Админка (`/admin`) защиты на уровне приложения не имеет — планируется
Basic Auth на уровне nginx (htpasswd) при деплое на сервер, в коде
ничего для этого нет и не должно быть (см. заметки ниже про
ADMIN_USERNAME/ADMIN_PASSWORD — их убрали как мёртвые переменные).

## JSON API (api.py)

Только чтение, все роуты под защитой из раздела выше:
- `GET /api/subjects` — список субъектов со счётчиком документов
- `GET /api/subjects/{id}` — субъект: папки с документами + документы
  без папки
- `GET /api/categories` — список категорий
- `GET /api/documents/{id}` — один документ целиком
- `GET /api/search?q=&subject_id=&category_id=&primary_only=` — поиск

## Главный экран мини-аппа (как сделано по факту)

- Поле поиска сверху (дёргает `/api/search?q=`)
- Чипы категорий — **одиночный переключатель**, не мультивыбор:
  тап включает фильтр по этой категории (сразу только `is_primary`),
  повторный тап — выключает. Есть кнопка "Показать все" — снимает
  фильтр по `primary_only`, но категория остаётся
- Если фильтр не активен — снизу список субъектов карточками
  (аватар с инициалами, имя, счётчик документов), тап → экран субъекта
- Сортировка везде — по issue_date, не по created_at

## Экран субъекта

Провалились в субъекта → папки блоками, в каждой её документы;
документы без папки — отдельным блоком внизу.

## Карточка документа

- Превью: тег категории, бейдж "Основной" (если есть), бейдж скорого
  истечения срока (если valid_until близко), заголовок,
  серия / номер / дата выдачи
- Кнопка "Раскрыть подробнее" → кем выдан (обрезается многоточием если
  длинно), срок действия, субъект
- Кнопки внизу: "Скачать" (сейчас **намеренно неактивна** — см. ниже) и
  "Скопировать" (реально работает — собирает текстовые поля в буфер
  через `navigator.clipboard`)

## Скачивание файла — ПЛАН, НЕ РЕАЛИЗОВАНО

Задумано так:
1. `Telegram.WebApp.downloadFile()` — нативный попап сохранения файла
   прямо внутри мини-аппа
2. Бэк параллельно шлёт тот же файл ботом (`sendDocument`) в чат —
   дублирующая копия для форварда

Бэк должен стримить байты из Google Drive по drive_file_id
(Drive API, `files.get` c `alt=media`), без локального кеша. Для этого
нужен сервисный аккаунт Google с доступом к папке документов —
это открытый вопрос, см. "Что осталось сделать".

## Админка

- `/admin` — хаб субъектов (крупные карточки), он же главная страница,
  отдельного дашборда нет
- `/admin/subjects/{id}` — карточка субъекта: папки, документы,
  переименование/удаление
- `/admin/documents`, `/admin/categories` — списки с CRUD
- Удаление занятого субъекта/категории блокируется и показывает **в
  каком именно документе используется** (не молча отказывает)
- Действия (править/удалить/добавить документ в папку) — иконками
  (Tabler Icons через CDN), не текстом
- Basic Auth — на уровне nginx при деплое, в приложении не реализован

## Бот (bot.py)

- `/start` — присылает кнопку открытия мини-аппа (WebApp) + показывает
  telegram id отправителя (чтобы удобно было прописать в
  ALLOWED_TELEGRAM_IDS)
- Больше пока ничего не реализовано: push-уведомления об истекающих
  документах (по notify_before_expiry/notify_period) — в планах,
  крона ещё нет, хотя apscheduler уже в requirements.txt
- Никакой загрузки документов через бота, только чтение

## Что сделано

- Модель данных, админка (CRUD + светлая тема + защита удаления) — готово
- JSON API + защита (initData + whitelist) — готово
